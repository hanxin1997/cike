# Windows 使用与验收

此分支构建 hanxin1997/cike 自己的源码，不再自动拉取上游。Windows 10/11 x64，使用完整 ZIP 目录运行。

## 安装与数据位置

从本仓库 Releases 下载 `CIKE-版本号-win-x64.zip`，将全部内容解压到当前账户可写的专用文件夹，例如 `D:\CIKE`。运行里面的 `CIKE.exe`；不要单独复制 EXE。

默认所有应用管理的数据在程序旁：

| 目录 | 内容 |
| --- | --- |
| `browsers` | Chromium 内核、相对路径标记、内核下载与解压暂存 |
| `data/profiles` | 浏览器环境、Cookie、站点存储和缓存 |
| `data/desktop`、`data/desktop-session` | 管理界面的数据与缓存 |
| `data/temp`、`data/logs`、`data/crashDumps` | 应用临时文件、日志、崩溃记录 |
| `data/updates` | 更新下载、程序备份、恢复状态 |
| `Downloads` | 网页下载的文件 |

设置页显示实际数据、内核和下载目录。应用会在首次启动前检查可写性及 Windows 私有权限；无法写入时明确报错，不自动回退 C 盘。Windows 系统自身的日志、预取等仍由系统管理。

需要自定义时可显式设置 `LFB_DATA`；该模式会把内核、下载、缓存等默认放到这个数据根内。程序目录整体移动后，新安装的内核标记和下载路径会重新解析。凭据受 Windows 当前账户保护，目录便携不保证跨用户或跨机器解密。

## 从旧试用版迁移

旧试用版没有新的自动更新器，必须手动安装一次。先退出旧版和全部环境，备份 `%USERPROFILE%\.local-fingerprint-browser`。

将旧目录中的配置文件、API 文件和 `profiles` 复制到新版 `data`。如旧版已经安装过内核，将旧 `browsers` 复制到新版同级的 `browsers`；旧标记若仍指向 C 盘，建议在设置重新安装内核生成相对标记。新旧数据不要直接合并或覆盖：请先使用空的新目录，保留旧备份供核对。

重开后检查环境列表、代理和已登录站点。确认保留的数据都可用后，再自行清理 C 盘旧副本；新版不自动删除旧数据。

## 更新

启动后自动检查 `hanxin1997/cike` 的正式 Releases，设置页也可手动检查。发现新版后由用户确认，程序下载并核对 SHA256、版本和包内路径，然后关闭环境、退出、替换程序并重启。正常更新保留 `data`、`browsers` 和 `Downloads`。

更新助手在新程序成功启动并确认后才清理程序备份。失败时恢复旧程序，并在下次启动显示错误和恢复位置。更新期间不要手动删除 `data/updates`。自定义数据根与安装目录不在同一盘时，使用手动更新。

手动更新应先退出应用，将新 ZIP 的程序文件复制到原目录，保留上述三个用户目录。不要用“删除整个旧文件夹”的方式升级。

此构建未配置 Windows 代码签名证书。SHA256 检查下载完整性，不等同于发布者签名。

## 构建和验收

在 Actions → Build Windows → Run workflow 构建当前仓库。默认只提供 14 天保留的测试 artifact；勾选 publish 后，所有检查通过才在本仓库发布当前 package.json 版本。正式版本不能重复发布，升级版本时同步 package.json/package-lock.json。

检查包括：应用自身下载内核、Windows 版本读取与安全解压、代理路由与认证、API 鉴权、ACL、原生沙盒与环境存储隔离、下载持久化、桌面操作、打包后真实下载内核、无环境变量时的便携目录，以及移动目录后继续启动。更新测试覆盖版本/资产选择、下载中断、非法 ZIP、替换与回滚。

本地不安装额外环境，完整 Electron/Chromium 测试在 GitHub Windows runner 上执行。每轮实际通过情况以当前 Actions 记录与实施方案为准；测试成功不能覆盖所有系统代理、杀毒软件、磁盘故障或第三方网站场景。
